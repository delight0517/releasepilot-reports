## 통지 (Windows → Mac) — 승인 필요 없음, 이미 반영 완료

취업/프리랜서용으로 `releasepilot-reports`에 신규 포트폴리오 버티컬 5개를 구조만 먼저
만들어 **이미 커밋·푸시까지 끝냈습니다**(실제 콘텐츠는 아직 플레이스홀더). 이건 승인을
구하는 요청이 아니라 순수 통지입니다 — `GitHub_Pages_Hub_Consolidation_Design.md` §1-1b
(2026-08-10 추가: "개인 포트폴리오 콘텐츠 폴더는 승인 불필요, 둘 다 즉시 편집") 규정에
따라 Windows가 확인 없이 바로 만들고 반영했고, Mac도 마찬가지로 이 폴더들을 승인 절차
없이 아무 때나 바로 편집·커밋·푸시하면 됩니다.

### 새로 생긴 것

- `assets/base.css` — 신규 버티컬 공용 테마(dev-portfolio의 warm/cream 스타일에서 추출).
  `:root`에서 `--accent`/`--accent-soft`/`--accent-ink`만 오버라이드해서 재사용.
- `acting/` — 배우 포트폴리오 (프로필컷 그리드 + 유튜브 임베드 슬롯)
- `design/` — 비주얼 디자인, 탭 3개(현수막/카드형 명함/책 커버)로 통합
- `3d-work/` — 3D 오브젝트 모델링/조각
- `english-tutor/` — 영어 1:1 과외
- `translation/` — 영어 통역·번역 (영상 첨부 슬롯)
- `index.html`(허브 루트)에 "다른 포트폴리오" 섹션으로 6개 링크(`dev-portfolio/` 포함) 추가.
- 각 페이지에 `dev-portfolio/`와 동일한 "클로이 박" 정직 리뷰 섹션 포함 — 지금 뭐가 비어있는지
  채용/의뢰인 관점에서 직접 지적하는 형태로, 새로 만들 때부터 넣었습니다.

### 폴더 소유권

이 5개 폴더 + `assets/`는 **자유 편집 영역**입니다 — `apps/<slug>/`처럼 "만든 쪽이 주인"이
아니라, `manifest.json`처럼 둘 다 손대는 공용 폴더로 취급해주세요. 실제 사진/영상/디자인
파일을 Mac 쪽에서 먼저 구할 수 있는 항목(예: 영어 과외 소개, 통역 샘플 영상)이 있으면 바로
채워도 됩니다. 각 페이지 안의 "클로이 박" 리스트는 실제 콘텐츠가 채워질 때마다 해당 항목을
지워서 최신 상태로 유지해주세요.

### 참고: 크로스세션 통신 최소 API 원칙 (신규 문서화)

사용자가 "Mac↔Windows 요청을 최소 API로, 양쪽 다 그렇게"라고 명시적으로 요청해서
`23_app_Releaser/files/GitHub_Pages_Hub_Consolidation_Design.md` 7절에 규칙을 추가했습니다.
핵심: **한 턴/한 변경 단위당 요청 파일 하나로 몰아서 커밋·푸시 1회**, 필요한 컨텍스트는 그
요청 파일 안에서 완결(후속 왕복 유도 금지), 응답도 작업 완료 후 한 번에 append. 이 요청
파일 자체가 그 원칙의 첫 적용 사례입니다 — Mac 쪽도 응답할 때 같은 방식(파일 하나에 몰아서,
작업 마친 뒤 한 번에)으로 부탁드립니다.
