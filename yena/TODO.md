# 김예나 포트폴리오 사이트 — 할 일 리포트

> 대상 사이트: https://delight0517.github.io/releasepilot-reports/yena/
> 이 폴더(`yena/`)는 [GitHub_Pages_Hub_Consolidation_Design.md 1-1b](../../23_app_Releaser/files/GitHub_Pages_Hub_Consolidation_Design.md)의
> "개인 포트폴리오 콘텐츠 폴더" 규칙 적용 대상입니다 — **Windows/Mac 세션 모두 승인
>절차 없이 자유롭게 이 폴더를 읽고, 수정하고, 커밋·푸시할 수 있습니다.** 다른
> 앱 폴더(`apps/<slug>/`)처럼 "만든 쪽이 주인"이 아니라, 김예나 포트폴리오라는
> 하나의 목적을 두 플랫폼이 같이 관리하는 폴더입니다.
>
> 이 파일은 "지금 사이트를 취업·포트폴리오용으로 완성하려면 무엇이 더 필요한가"를
> 추적하는 작업 리포트입니다. 공개 페이지(`index.html`)에는 노출되지 않고,
> Windows/Mac 세션과 사용자가 참고하는 내부 작업 문서입니다.

---

## A. 예나 님에게 받아야 할 자료 (취업/포트폴리오 완성용)

각 항목은 `[ ] open` / `[x] done`으로 상태를 표시합니다. 받은 자료를 반영했으면
체크하고, 어디에 반영했는지 한 줄 남겨주세요.

- [ ] **프로필 사진** — 본인이 이 용도(공개 추천서 사이트)로 쓰는 것에 동의한
      사진 1장 이상. 파일로 직접 전달받거나, 본인이 지정한 공개 URL만 사용.
      (`yena/content.json`의 `photoUrl` 필드에 반영)
- [ ] **경력 연차·수상명 최종 확인** — 현재 페이지의 "6년 과외 / 3년 교육
      플랫폼 / Hackathon 우수상" 등 숫자·명칭이 실제 이력서·증빙과 정확히
      일치하는지 본인 확인. 채용 담당자가 이력서와 대조했을 때 어긋나면
      신뢰도에 직접 타격이 있음 — 원문에서도 이미 강조된 부분.
- [ ] **실제 강의 자료/커리큘럼 샘플** — 수업 계획서, 워크시트, 활동지 등
      (소속 기관·학부모 동의가 필요한 자료는 제외하고 본인이 직접 만든 것만).
      "말로만 하는 경력"이 아니라 실물 증거로 신뢰도를 크게 올려줄 자료.
- [ ] **학부모/동료 피드백 인용문** — 원하는 경우, 실명 대신 이니셜이나 "학부모
      A", "동료 교사 B" 형태로 익명화해서 사용.
- [ ] **프로젝트·해커톤 결과물** — 스크린샷, 발표자료, 또는 공개 가능한 링크.
- [ ] **이력서(PDF) 또는 LinkedIn/포트폴리오 링크** — 지원 시 이 페이지와 함께
      보여줄 정식 이력서. 페이지에 다운로드/링크 버튼으로 추가 예정.
- [ ] **연락처 공개 여부 결정** — 채용 담당자가 바로 연락할 수 있는 이메일/폼을
      페이지에 넣을지, 넣는다면 어떤 채널(개인 이메일 노출 여부는 예나 님이
      직접 판단해야 하는 부분 — Claude가 임의로 넣지 않음).

## B. 향후 발전 가능성 (로드맵 아이디어)

우선순위 없이 나열 — 위 A 항목이 채워지는 대로 순서대로 검토.

1. **실제 수업 사례 갤러리** — 연령군별 수업 스타일/활동을 짧은 스토리 카드로.
2. **성장 스토리 카드** — "이 학생은 이런 어려움이 있었고, 이렇게 접근해서
   이런 변화가 있었다" 형태의 익명화된 사례 1~3개.
3. **자료실/블로그 섹션** — 교육 콘텐츠, 수업 후기, 최신 소식을 계속 쌓는
   공간 (지금 `updatesPlaceholder` 섹션이 이걸 위한 자리).
4. **영문 버전** — 국제학교/외국계 기관 지원을 염두에 둔다면 영문 페이지
   별도 제작 고려.
5. **간단한 문의/지원 CTA** — A의 연락처 결정이 끝난 뒤에만 진행.
6. **업데이트 로그** — 페이지 하단에 "무엇이 언제 추가됐는지" 짧은 타임라인.

## C. 편집 규칙 (Windows ↔ Mac 공용)

- 이 폴더(`yena/`)는 승인 없이 양쪽 세션 모두 즉시 편집 가능 — `requests/`에
  올리고 기다릴 필요 없음.
- 실제로 A 항목을 반영했으면 이 파일에 `## 진행 로그`로 날짜+기기+무엇을
  했는지 한 줄씩 append. (아래 진행 로그 섹션에 이어서 적기)
- 사진/개인정보처럼 민감한 자료를 다루는 항목(A의 프로필 사진, 연락처 공개)은
  **본인(예나 님)의 명시적 확인 없이 임의로 채우지 않는다** — 이건 두 플랫폼
  모두 지켜야 하는 공통 원칙.
