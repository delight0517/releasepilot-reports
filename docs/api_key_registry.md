# 중앙 API 관리 대장 — 운영 규칙

**만든 이유(2026-08-26 사용자 요청)**: "API도 중앙식으로 전체를 박새로이가 관리해서,
더 이상 내가 관리하거나 타이핑하지 않아도 되는 시스템."

방향은 맞다. 다만 **그대로 하면 안 되는 부분이 하나 있어서** 그 부분만 바꿔서 만들었다.

## 절대 규칙 — 이 저장소에 실제 키를 두지 않는다

`releasepilot-reports`는 GitHub Pages로 **전 세계에 공개**되는 저장소다.
여기에 토큰을 커밋하면 비공개 폴더에 넣든, 파일명을 숨기든, 나중에 지우든
**커밋 순간 이미 유출**이다(git 히스토리와 각종 크롤러에 남는다).

그래서 중앙 관리를 이렇게 나눴다.

| | 어디에 두나 | 무엇이 들어가나 |
|---|---|---|
| **대장(공개 OK)** | `apps/_shared/api_registry.json` | 키가 **있는지 / 어디에 있는지 / 발급됐는지 / 언제 확인했는지** |
| **값(비공개)** | Render 환경변수, 기기 로컬 파일, 브라우저 localStorage | 실제 토큰 문자열 |

이렇게 하면 "사장님이 관리하거나 타이핑하지 않아도 되는" 목적은 그대로 달성된다 —
**무슨 키가 어떤 상태인지 추적하는 일**이 사람 머리에서 대장으로 옮겨가기 때문이다.
사장님이 직접 해야 하는 건 최초 발급 한 번뿐이고, 그 뒤로는 대장이 기억한다.

## 대장 스키마

`apps/_shared/api_registry.json`의 `keys[]` 각 항목:

| 필드 | 설명 |
|---|---|
| `id` | 영문 snake_case 고유 식별자 |
| `label` | 사람이 읽는 이름 |
| `usedBy` | 이 키를 쓰는 앱/기능 목록 |
| `storage` | `render-env` / `windows-local` / `mac-local` / `browser-localstorage` / `pending` / `unknown` |
| `location` | 구체적 보관 위치(경로나 서비스명) — **값이 아니라 위치만** |
| `status` | `issued`(발급·확인됨) / `assumed-issued`(작동한다고 적혀 있으나 근거 없음) / `not-issued` / `revoked` |
| `verifiedAt` | 마지막으로 **실제로** 확인한 날짜 |
| `verifiedHow` | 어떻게 확인했는지(예: "sendMessage 호출해 ok:true 확인") |
| `notes` | 주의사항 |

`assumed-issued`가 이 스키마의 핵심이다. 기획서에 "🟢 작동 중"이라고 적혀 있다는 것과
실제로 작동한다는 것은 다르기 때문에, 근거 없이 작동 중이라 적힌 항목을 따로 구분해
계속 눈에 띄게 남긴다.

## 점검 도구

```bash
python3 scripts/check_api_registry.py          # 사람이 읽는 표
python3 scripts/check_api_registry.py --json   # 기계용
```

두 가지를 한 번에 한다.

1. **스키마 검증** — 필수 필드 누락, id 중복, 이상한 status, 확인일자 없는 발급건,
   보관 위치 미상 항목을 집계한다.
2. **비밀키 유출 검사** — 대장에 실제 토큰처럼 보이는 문자열이 들어갔는지 정규식으로 찾는다.
   탐지 대상: 텔레그램 봇 토큰 / OpenAI 계열 `sk-` / GitHub `ghp_` 계열 /
   노션 `secret_`·`ntn_` / Google `AIza` / `Bearer` 헤더.
   발견하면 **값을 출력하지 않고 앞 6자만 보여준 뒤 종료코드 2**로 끝난다.

종료 코드: `0` 이상 없음 / `1` 스키마 문제 / `2` 비밀키 발견(커밋 금지).
