# 서버 운영 방식 선택 가이드 — 로컬 PC 의존 vs 온라인 호스팅 vs AI 처리 방식 (2026-08-19)

> 이 문서는 특정 인물의 로드맵이 아니라, **서버가 필요한 자기 앱을 여러 개 굴리는
> 개발자가 매번 같은 결정(어디에 올릴지, AI 처리를 어떻게 돌릴지)을 반복해서 내려야
> 할 때 참고하는 범용 의사결정 가이드**다. 오늘(2026-08-19) 브레인와이어(Node/Express
> 개인 앱)를 실제 사례로 조사한 내용을 일반화했다. 숫자는 조사 당시 확인한 값이며,
> 각 서비스의 요금/정책은 바뀔 수 있으므로 결정 직전에는 항상 공식 페이지에서
> 재확인할 것.

## 1. 지금 뭘 쓰고 있는지부터 파악

Node/Express 같은 "상시 켜져 있어야 응답하는" 서버 앱을 처음 만들면 대부분 이렇게
시작한다:

- **로컬 PC에서 상시 실행 + Cloudflare Quick Tunnel**로 외부에 노출.
- 완전 무료, 설정이 가장 쉽다 — `cloudflared tunnel --url http://localhost:PORT`
  한 줄이면 바로 공인 URL이 생긴다.
- 하지만 구조적 한계가 있다:
  - PC가 꺼지거나 잠들면 서비스 전체가 즉시 중단된다(35Closer의 `autoIdle`/
    `keepAwake` 같은 절전 관리가 없으면 특히 취약).
  - Quick Tunnel URL은 **매번 재시작할 때마다 바뀐다** — 그리고 브레인와이어에서
    실제로 겪은 문제로, 연결이 자주 끊긴다.
  - 앱스토어/플레이 콘솔 제출용 "백엔드 URL" 같은 **고정 URL이 필요한 용도로는
    부적합**하다(URL이 계속 바뀌면 심사 담당자가 접근 못 함).

## 2. 온라인 상시 호스팅 옵션 비교

로컬 PC 의존을 끊으려면 클라우드에 올려야 한다. 오늘 확인한 네 가지 선택지:

### Cloudflare Workers / Containers
- Cloudflare Workers는 **서버리스** 실행 모델이라 Express처럼 "계속 켜져서 리스닝하는
  프로세스" 자체를 올릴 수 없다 — Node/Express를 그대로 쓰는 앱에는 구조적으로
  안 맞는다.
- Cloudflare Containers는 상시 프로세스를 올릴 수 있는 신규 기능이지만, 조사 시점
  기준 **문서/생태계가 아직 얕다** — 검증된 선택지로 권하기엔 이르다.

### Render (무료 티어)
- 완전 무료지만, **15분 동안 인바운드 트래픽이 없으면 서비스가 슬립**된다
  (Render 공식 문서 확인: "Render spins down a Free web service that goes 15
  minutes without receiving any inbound traffic").
- 슬립 후 첫 요청이 오면 다시 깨어나는 데 **약 1분(콜드스타트)**이 걸린다(공식
  문서: "This process takes about one minute").
- 상시 유지하려면 유료 인스턴스로 업그레이드해야 하며, 이 경우 슬립 기능 자체가
  제거된다. **가장 저렴한 유료(Starter) 인스턴스는 월 약 $7**로 알려져 있으나,
  정확한 현재가는 render.com/pricing 공식 페이지에서 재확인 필요(오늘 자동
  조회로는 구체적 가격 숫자를 페이지에서 직접 확인하지 못함 — **확인 필요**로
  남김).

### Railway
- **Free Trial**: $5 상당 크레딧, 30일 제한 — 체험용이라 상시 운영에는 부적합
  (기간 만료, 리소스 제한, 로그 7일만 보관).
- **Hobby 플랜**: 월 $5(월 $5 크레딧 포함)부터 상시 운영 가능.
- **Pro 플랜**: 월 $20(월 $20 크레딧 포함).
- (Railway 공식 pricing 페이지 확인, 2026-08-19)

### Fly.io
- **사용량 기반 과금** — 실제 프로비저닝된 리소스에 시간 단위로 비례 청구.
- 최소 사양(`shared-cpu-1x` + 256MB)을 상시 가동할 경우 기본 컴퓨트 비용은
  **월 약 $2.02**, 여기에 볼륨 스토리지($0.15/GB/월), 데이터 전송($0.02~$0.12/GB)
  등이 추가될 수 있어 실질적으로는 **월 약 $2~5** 범위로 예상된다(Fly.io 공식
  pricing 문서 확인, 2026-08-19).
- 콜드스타트 없이 상시 가동 가능하고, 영구 볼륨(디스크)도 붙일 수 있다.

## 3. AI 처리 방식 선택 — 실시간/자동 배치 vs 무비용 수동 트리거

서버를 어디에 올릴지와 별개로, 그 서버 안에서 AI(예: Claude) 처리를 어떻게 돌릴지도
독립적으로 결정해야 한다.

### 옵션 A — 실시간 API 키 + 자동 배치(cron)
- API 키를 서버에 심어두고 cron 등으로 정해진 시간마다 자동으로 AI 처리를 돌린다.
- **PC/세션이 없어도 100% 자동으로 진행된다.**
- 하지만 API 사용료가 실제로 발생한다. 정확한 월 예상 비용은 처리하는 배치
  크기(요청 수·토큰 양)에 따라 달라지므로 **확인 필요**로 남긴다 — 지어낸 금액을
  넣지 않는다.

### 옵션 B — API 키 없이, 사람이 Claude 세션을 열어 "처리해줘"라고 트리거하는 배치
- API 사용료 없이 **0 비용**을 유지할 수 있다.
- 하지만 사람이 직접 세션을 열고 요청해야만 처리가 진행된다 — 완전 자동 스케줄은
  안 된다.

### 이 둘 사이의 모순을 명확히 짚어야 한다
"API 비용은 0으로 유지하면서, 동시에 완전 무인 자동 스케줄로 돌리고 싶다"는 요구는
**논리적으로 성립하지 않는다**:

- 옵션 B를 스케줄러(cron 등)로 무인 실행하게 만들면, 결국 그 스케줄러가 Claude
  세션/API를 호출하는 시점에 **API 호출이 발생**하게 되어 "비용 0" 전제가
  깨진다(둘 중 하나: API 키를 심거나, 아니면 무언가가 호출을 실제로 발생시켜야
  하므로).
- 그 무인 실행을 돌릴 스케줄러 자체는 **항상 켜져 있는 기기**(로컬 PC든 클라우드
  인스턴스든)가 있어야 한다 — 그런데 그건 애초에 1절에서 벗어나려던 "PC 상시
  의존 제거"라는 목적과도 다시 충돌한다.

즉 "비용 0"과 "완전 무인 자동"은 동시에 만족할 수 없고, 어느 한쪽을 포기해야 한다.
이 선택은 이 가이드의 4절에서 조합으로 정리한다.

## 4. 내 상황에 맞는 조합 고르기

- **비용 0 유지가 우선인 조합**: 로컬 PC 상시 실행(또는 이미 켜둔 저사양 클라우드
  인스턴스) + 사람이 세션을 열 때만 처리되는 수동 트리거(옵션 B). 완전 자동
  스케줄은 포기한다.
- **완전 자동이 우선인 조합**: 상시 호스팅(Render 유료/Railway Hobby/Fly.io 중
  하나) + 실시간 API 키 + cron 자동 배치(옵션 A). API 사용료가 발생하는 것을
  받아들인다.
- 앱스토어 심사처럼 **고정 URL이 반드시 필요한 경우**는 1절의 로컬+Quick Tunnel
  조합을 자동으로 배제하고 2절의 상시 호스팅 중 하나를 선택해야 한다.

## 확인 필요 목록 (지어내지 않고 남겨둔 항목)

- Render Starter(최저가 유료 인스턴스)의 정확한 현재 월 가격 — 공식 문서에서
  "월 약 $7"이라는 값이 알려져 있으나, 오늘 자동 조회로는 pricing 페이지에서
  구체 숫자를 직접 확인하지 못함. 결정 직전 render.com/pricing에서 재확인.
- 실시간 API 자동 배치(옵션 A)의 정확한 월 예상 비용 — 배치 크기(요청 수/토큰
  양)에 따라 달라지므로 일반화된 숫자를 제시하지 않음.
