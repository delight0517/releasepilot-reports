01

왜 이 점검을 했나

Claude Code에 SEO 점검 도구(Claude SEO, 오픈소스)를 설치하고, 이 사용자가 운영 중인 공개 자산 4곳 — 릴리저 리포트 허브, 개발 포트폴리오, 브레인와이어 앱, 6VPN 개인정보처리방침 — 을 실제 크롤러가 보는 그대로(HTML 파싱, robots.txt/sitemap.xml 응답, 메타 태그) 확인했다. "예쁘게 보이는가"가 아니라 "검색엔진이 실제로 찾아서 색인할 수 있는가"만 봤다.

02

🔴 Critical — 지금 손해 보고 있는 것

CRITICALrobots.txt를 아무도 못 읽고 있었다 → 확인함

GitHub Pages는 크롤러가 도메인 루트(delight0517.github.io/robots.txt)만 읽는데, 거기는 404였다. 서브경로에 만들어둔 releasepilot-reports/robots.txt는 구글도 네이버도 못 본다 — 사이트맵 선언까지 같이 무시되고 있었다. 커스텀 도메인을 붙이거나, 사이트맵을 서치콘솔/네이버서치어드바이저에 직접 제출해야 우회된다.

CRITICAL사이트맵이 실제 페이지의 43%만 담고 있었다 → 고침, 39개로 복구

로컬에 실제 페이지 42개(공개 대상 39개, 나머지 3개는 사이트 운영자가 이미 noindex로 의도적 비공개) 중 사이트맵엔 18개뿐이었다. 개발 포트폴리오, 앱 소개 페이지 대부분, 다운로드 페이지가 빠져 있었다. scripts/generate_sitemap.py를 새로 만들어 저장소를 직접 스캔하도록 바꿨고, 지금 sitemap.xml은 39개로 자동 복구됐다.

CRITICAL브레인와이어는 검색엔진엔 사실상 빈 페이지

서버가 주는 HTML 32KB 중 실제 텍스트가 91자뿐, <h1> 없음, <noscript> 없음, canonical 없음, robots.txt/sitemap.xml 둘 다 404. 완전한 클라이언트 렌더링(SPA)이라 크롤러는 메뉴 라벨만 본다. prerender나 서버사이드 렌더링, 최소한 <noscript> 대체 텍스트가 필요하다.

03

🟠 High

HIGH구조화 데이터(schema)가 전 사이트 0건

42개 페이지 어디에도 JSON-LD가 없다. 취업용 포트폴리오라면 Person(본인) + SoftwareApplication(만든 앱들) + BreadcrumbList가 가장 효과 큰 자리 — dev-portfolio는 og:type=profile을 쓰면서 정작 Person 스키마가 없다.

HIGH포트폴리오 대표 이미지가 남의 CDN에 걸려있음

dev-portfolio의 og:image가 브런치 카카오 CDN(img1.kakaocdn.net/...?fname=http://t1.kakaocdn.net/...)을 가리킨다. 지금은 200으로 뜨지만 남의 서비스라 언제든 끊길 수 있고, URL 안에 http://가 섞여 있다. 자기 저장소 이미지로 옮기는 게 안전하다.

HIGH6VPN 개인정보처리방침 — 메타 정보 전무

meta description 없음, canonical 없음, OG 전혀 없음, <h1>이 2개(한글/영문)다. 법적 필수 문서라 순위 욕심낼 페이지는 아니지만, 스토어 심사·링크 공유 시 미리보기가 깨진다.

04

🟡 Medium

MEDIUM콘텐츠가 얇다

메인 258단어, dev-portfolio 216단어. 포트폴리오는 검색·필터가 JS 기반이라 크롤러엔 더 적게 보인다.

MEDIUMllms.txt 없음 — AI 검색(GEO) 대응 0

3개 사이트 전부 404. ChatGPT·Perplexity·AI Overviews가 이 사이트를 인용할 근거 파일이 아예 없다. 지금 만들어두면 선점 효과가 큰 항목.

MEDIUM브레인와이어 og:image가 상대경로

/icon.svg로 돼 있어 카톡·슬랙 공유 시 썸네일이 안 뜬다. 절대 URL(https://brainwire-f2gf.onrender.com/icon.svg)로 바꿔야 한다.

05

잘 돼 있는 것

메인·포트폴리오의 title·description 길이가 적정하고 canonical·OG·트위터 카드가 제대로 붙어있다. design/3d-work/english-tutor 페이지도 canonical + OG 5개까지 깔끔하다 (이 3개는 사이트 운영자가 이미 noindex로 비공개 처리해둔 페이지라 이번 사이트맵 복구 대상에서도 그대로 제외했다). 기본기는 잡혀 있고, 막힌 건 "색인 경로"와 "구조화 데이터" 두 축이었다.

06

이번에 바로 처리한 것

  • ☑ 사이트맵 자동 생성 스크립트 신설 — scripts/generate_sitemap.py. 저장소를 직접 스캔해 모든 index.html을 찾고, 운영자가 이미 noindex 처리해둔 페이지는 존중해서 제외한다. 앞으로 페이지를 추가해도 다시 빠지지 않는다.
