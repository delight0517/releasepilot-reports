Render 유료 전환, 돈 낼 만한가?

추정이 아니라 실측입니다. 오늘 직접 잰 숫자와 Render 공식 문서만 씁니다.

약 61초 → 5.6초
폰에서 봇에게 메시지를 보냈을 때, 실사용 대부분의 경우 답이 오기까지

한 줄 결론

세일즈 빼고 먼저.

평상시 속도는 이미 무료로 고쳤습니다. 오늘 요청마다 돌던 git pull을 걷어냈고, 그건 돈과 무관했습니다.

유료가 사는 건 딱 하나 — "가끔 아예 답이 안 오는" 문제입니다. 그런데 형의 사용 패턴에서는 그 "가끔"이 사실상 거의 매번입니다. 이유는 3번에 있습니다.

2. 메시지 한 건에 무슨 일이 벌어지나

코드를 따라가서 센 것이지 어림짐작이 아닙니다.

봇에 답장 하나를 보내면 서버는 저장소를 5번 건드립니다 — 계정 조회, 상태 읽기, 상태 쓰기, 잡큐 읽기, 잡큐 쓰기. 고치기 전에는 그 5번이 전부 GitHub 왕복이었습니다.

5회 × 1.86초 = 9.3초

이 계산이 맞다는 독립적 증거: 2026-08-22에 실제로 잰 웹훅 왕복이 7.9초였습니다. 코드에서 센 예측치와 자릿수가 맞습니다 — 즉 그때의 느림은 콜드스타트가 아니라 이 git pull 더미였습니다.

오늘 읽기 경로에 60초 캐시를 넣어 5회 → 3회로 줄였습니다. 쓰기는 일부러 그대로 뒀습니다 — 오래된 사본으로 쓰면 다른 기기가 올린 데이터를 덮어쓸 수 있고 실제로 그럴 뻔한 적이 있습니다. 읽기만 빨라지고 안전장치는 그대로입니다.

3. 형의 사용 패턴이 최악의 궁합인 이유

이 리포트에서 제일 중요한 부분입니다.

무료 플랜은 15분간 아무도 안 부르면 서버를 끕니다. 그런데 개인 학습 봇을 15분마다 부르는 사람은 없습니다. 생각날 때 한 번, 자기 전에 한 번 던지죠.

즉 형이 보내는 거의 모든 메시지가 "꺼져 있는 서버"를 깨우는 첫 메시지입니다. 콜드스타트는 예외 상황이 아니라 형에겐 기본값입니다.

실제로 겪으신 일입니다. 오늘 저녁 19:58에 보낸 메시지에 답이 없었고, 로그를 보니 서버가 그 직후 재기동했습니다. 메시지가 서버가 깨어나는 사이에 끼어 있었던 겁니다.

5. 그래서 어떤 셋업을 하면 되나

데이터 이전 작업은 없습니다. 운이 아니라 설계 덕분입니다 — 파일을 쓸 때마다 그 자리에서 GitHub에 커밋+푸시하므로, 컨테이너에는 "아직 안 올라간 데이터"가 존재할 수 없습니다. 컨테이너 안의 사본은 정본이 아니라 캐시고, 지금도 배포마다 날아갔다 다시 받고 있습니다.

✓
0단계 — 요청마다 하던 git pull 제거이미 완료(오늘). 비용 0원. 평상시 속도는 이걸로 끝났습니다.
1
1단계 — 플랜을 Starter로render.yaml의 plan: free 한 줄만 바꾸면 됩니다. 환경변수도 데이터도 그대로 유지되고, 되돌리기도 같은 한 줄입니다.
2
2단계 — 영구 디스크 (선택)붙이면 재배포마다 하던 11MB 재clone(4.35초)이 사라집니다. 없어도 동작에는 지장 없습니다.
딱 하나 제가 확인 못 한 것 — 가격입니다. Render 요금 페이지가 스크립트로 그려져 값을 못 읽었습니다. 추측해서 적지 않겠습니다. 대시보드에서 월 요금을 확인하시고 위 "약 11배 / 유실 0건"과 견주어 판단해주세요.

6. 그다음 펼쳐지는 서비스

형이 상담에서 답한 "적응형 퀴즈 교육자"가 도착점입니다. 서버가 항상 깨어 있어야 성립하는 것부터 순서대로.

1
채팅 퀴즈앱을 열지 않아도 텔레그램에서 한 문제씩 받고, 그냥 답장하면 채점. 4단계 질문(인출·연결·적용·창조)은 이미 만들어지고 있고 앱을 열어야만 보이는 상태입니다. 부품이 다 있어 제일 빠릅니다.
2
영상 던지면 학습유튜브 링크를 채팅에 붙이면 자막을 받아 요약하고 바로 퀴즈로. 자막 수집기는 이미 서버에 있습니다.
3
주제 지정 학습주제만 말하면 커리큘럼을 짜서 매일 한 조각씩. 새로 설계해야 해서 가장 오래 걸립니다.
왜 서버가 항상 깨어 있어야 하나: 1·2단계는 형이 먼저 말을 거는 방식입니다("퀴즈 시작해줘", 링크 붙여넣기). 그 첫 마디가 매번 60초를 기다리거나 유실되면, 기능이 아무리 완성돼도 결국 안 쓰게 됩니다. 3단계는 서버가 먼저 보내는 방식이라 깨어 있지 않으면 성립조차 안 합니다.

7. 정직하게, 사지 말아야 할 이유

세일즈맨처럼 해달라고 하셨지만 반대편도 적습니다.

  • 연속 대화 중 속도는 1초도 안 빨라집니다. 그건 오늘 무료로 끝냈습니다.
  • 5.6초는 여전히 남습니다. 쓰기 경로의 GitHub 왕복은 안전 때문에 일부러 남긴 것이라 유료여도 그대로입니다.
  • 지금 급하지 않다면 3단계(서버가 먼저 보내는 학습)를 실제로 만들 때 전환해도 늦지 않습니다. 그때는 선택이 아니라 필수가 됩니다.

그럼에도 제 추천은 전환입니다 — 이유는 속도가 아니라 유실입니다. 답이 늦는 건 참을 수 있지만, 보낸 게 사라지면 그 도구는 신뢰를 잃고 안 쓰게 됩니다.
