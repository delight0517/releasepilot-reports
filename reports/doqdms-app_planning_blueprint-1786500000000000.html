DOQDMS — 위치 기반 교회 예배 검색 웹앱

기획 단계(Planning-only) · releasepilot-hub/apps/doqdms에 원본 기획서 등록됨 · 2026-08-12 작성 · 아직 코드/저장소 없음

한 줄 정의

지금 내 위치에서 가까운 교회를 찾고, 그 교회의 예배 시간표 · 온라인 예배 영상 유무 · 가는 법(대중교통 소요시간)까지 한 화면에서 확인할 수 있는 지도 기반 검색 서비스. MVP는 네이티브 앱이 아니라 웹사이트(모바일 웹 최적화) 형태로 먼저 만든다.

1. 배경

네이버지도·카카오맵 같은 범용 지도 서비스는 "교회"를 장소(POI)로만 보여줄 뿐, 예배 시간표·온라인 예배 영상 유무·예배 규모 같은 종교시설 특화 정보를 구조화해 보여주지 않는다. 타지에서 새로 교회를 찾는 사람은 결국 교회 홈페이지를 하나씩 들어가 확인해야 하는데, 홈페이지가 없거나 오래된 경우가 많다. DOQDMS는 이 파편화된 정보(위치 + 예배 시간표 + 온라인 영상)를 한 곳에 모아 지도 위에서 바로 비교·필터링할 수 있게 한다.

2. 핵심 사용자 흐름

  1. 현재 위치에서 시작 — Geolocation API로 위치를 얻고, 권한 거부 시 수동 주소 검색으로 대체.
  2. 가까운 교회 검색 — 반경(1/3/5/10km) 내 등록 교회를 거리순으로 반환.
  3. 웹사이트 링크 — 각 교회 카드에 공식 홈페이지 노출(없으면 "홈페이지 없음" 표시).
  4. 지도 표시 — 결과를 지도 위 마커로 표시, 교단/규모/온라인 예배 여부로 아이콘 색상 구분.
  5. 대중교통 길찾기 — 지도 플랫폼 API 연동으로 소요시간·환승 정보 표시(자체 경로 엔진 없이 기존 API 호출).
  6. 온라인 예배 영상 존재 확인 — 유튜브/홈페이지에서 "실시간 예배", "주일예배 다시보기" 류 링크 탐지 → 배지 부여.
  7. 예배 규모 추정 — 예배 영상의 좌석 점유율/조회수 등 간접 지표로 소·중·대규모 라벨 추정 (고난도 — MVP 이후).
  8. 커뮤니티 + 필터 — 교단/언어/온라인 예배 여부/규모/주차 여부 필터, 사용자 한마디(MVP 이후).

3. 데이터 파이프라인 — 크롤링

1차: 네이버지도 업체 정보 · 2차: 교회 공식 홈페이지 · 3차: 교회 유튜브 채널

법적 리스크: 네이버지도를 자체 브라우저 자동화로 직접 스크래핑하는 방식은 이용약관 위반 소지가 있다. 착수 전 (a) 라이선스 허용 범위의 오픈 API부터 확인하고, (b) 안 되는 항목은 "교회가 직접 등록/수정하는 관리자 페이지"로 전환하는 셀프 등록 옵션을 함께 설계해야 한다 — 법무/약관 재확인 전에는 실제 크롤러 코드를 실행하지 않는다.

월 1회 배치로 재크롤링해 정보를 최신화하고, 교회별로 lastCrawledAt을 기록해 화면에 "정보 갱신일"을 노출한다.

4. MVP 우선순위

우선순위기능비고
P0현재 위치, 인근 검색, 지도 표시핵심 골격
P0홈페이지 링크, 기본 필터(교단/거리)
P1대중교통 길찾기/소요시간지도 API 연동
P1온라인 예배 영상 유무 배지유튜브 링크 탐지만
P2커뮤니티(리뷰/한마디)
P2예배 영상 기반 규모 추정영상 분석 R&D 필요

5. 로드맵

  1. Phase 0 — 기획 확정 (이 문서)
  2. Phase 1 — 특정 지역 20~30개 교회 수동 시드 데이터 구축(크롤러 없이 MVP 시연 가능)
  3. Phase 2 — 웹사이트 MVP 출시 (P0/P1)
  4. Phase 3 — 크롤링 자동화 + 월간 갱신 배치 (법무 확인 후, 또는 셀프 등록 전환)
  5. Phase 4 — 커뮤니티/필터 고도화, 예배 규모 추정 R&D

6. 열린 질문

  • 네이버지도 크롤링 허용 범위 — 안 되면 셀프 등록형으로 전환할지
  • 대중교통 길찾기 API를 카카오/네이버/구글 중 어디로 쓸지 (쿼터·비용·정확도 비교)
  • 예배 규모 추정을 영상 분석까지 할지, 조회수/구독자수 같은 간접 지표로 단순화할지
  • 초기 타깃 지역(전국 vs 특정 도시)과 시드 데이터 확보 방법(수동 조사 vs 외주)
