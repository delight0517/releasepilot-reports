기획서와 코드는 있지만, "24시간 무인 활성화"는 아직 아닙니다. 2026-08-25 리포트에 3대 봇이 🟢 24h 작동 중이라 적혀 있는데, 같은 저장소의 2026-08-24 실측 리포트는 그 서버가 Render 무료 플랜이라고 기록하고 있습니다. 무료 플랜은 15분 무활동이면 잠들기 때문에 두 문장은 동시에 참일 수 없습니다. 지금 상태는 "켜짐"이 아니라 "부를 때만 1분 걸려 깨어나는 반쯤 켜짐"입니다. 이걸 진짜 24시간으로 바꾸는 값이 월 $7부터입니다(아래 7번).

이건 이미 2026-08-24 실측 리포트가 숫자로 증명해 둔 내용입니다 — 여기서는 요약만 합니다.

핵심은 속도가 아니라 유실입니다. 개인 비서 봇을 15분마다 부르는 사람은 없으므로, 사장님이 보내는 거의 모든 메시지가 "잠든 서버를 깨우는 첫 메시지"가 됩니다. 즉 콜드스타트가 예외가 아니라 기본값입니다.

3. 사장님이 원하는 기능들은 전부 "서버가 먼저 말 거는" 쪽에 있다

이번에 추가로 주신 요청 — 브레인와이어부터 세콤이 알바를 찾아주는 것까지 — 을 구조로 분류했습니다.

사장님이 "이것들이 활성화되려면 결국 서버나 n8n이 있어야 하는 것 아니냐"고 물으신 건 정확한 진단입니다. 위 표에서 굵게 표시된 항목 — 매일 배달, 4시간마다 재질문, 알바 자동 탐색 — 은 전부 서버가 먼저 말을 거는 구조라, 잠드는 서버에서는 기능을 아무리 잘 만들어도 원리적으로 실행될 수 없습니다. 지금 세콤 팔로업이 안 도는 이유도 코드 문제가 아니라 여기에 있습니다.

단, "알바 자동 탐색"은 아직 기획서에 없는 새 요청입니다

세콤 기획안에 적힌 것은 "방송 섭외 들어왔을 때 가능한 시간대를 되묻는다"까지입니다. 먼저 나가서 알바/외주 공고를 찾아오는 기능은 기획서에 없습니다. 제가 없는 걸 있다고 적지 않기 위해 별도 신규 항목으로 표시해 둡니다 — 어느 채널(알바몬·크몽·인스타 DM·이메일)을 대상으로 할지만 정해주시면 그때 설계에 넣겠습니다.

4. "텔레그램으로 시켜도 아무리 기다려도 진행이 안 된다" — 원인 분석

사장님 가설: "맥에서 작업했는데 그게 윈도우에 전달이 안 돼서 그런가 싶다." 결론부터 — 맞습니다. 그리고 그 증거가 저장소에 그대로 남아 있습니다.

원인 ① 맥은 텔레그램에 아예 접속을 못 합니다 (구조적)

맥에서는 telegram.org 전체가 사장님 본인의 4VPN Blocker(자기통제 앱)에 의해 /etc/hosts에서 0.0.0.0으로 차단돼 있습니다. 그래서 맥 세션은 텔레그램으로 아무것도 못 보냅니다 — 대신 requests/ 큐에 "윈도우가 대신 보내달라"는 요청 파일을 남깁니다. (이건 본인 자기통제 장치라 우회하지 않는 것이 원칙입니다.)

즉 사장님이 텔레그램으로 명령을 던졌을 때, 그 일이 맥 쪽 일이면 맥은 답을 보낼 수단 자체가 없습니다. 기다려도 안 오는 게 당연합니다.

원인 ② 그 큐에는 폴링이 없습니다 — 상대 PC가 켜져야만 알아차립니다

requests/README.md가 명시합니다: "No polling/cron needed to notice new requests — check when a session starts." 즉 요청이 전달되려면 상대 기기에서 세션이 실제로 시작돼야 합니다. 윈도우 PC가 꺼져 있는 동안은 아무 일도 일어나지 않습니다.

실제 사례: 2026-08-22 세콤 텔레그램 발송 요청은 2일간 방치됐다가 2026-08-24에야 윈도우가 처리했습니다. 그때 윈도우 세션이 직접 이런 메모를 남겼습니다 — "다음부터는 이런 차단-경로 요청이 open 상태로 오래 방치되지 않도록 세션 시작 스캔에서 더 눈에 띄게 표시하는 게 좋겠음."

원인 ③ 답은 이미 와 있는데 사장님께 도달하지 않습니다 (가장 뜻밖의 발견)

오늘 제가 만든 점검 도구(scripts/check_request_queue.py)를 실제로 돌린 결과입니다.

세 건 전부 답변이 이미 달려 있습니다. 즉 "상대가 일을 안 한 것"이 아니라, 일은 끝났는데 그 결과가 사장님께 전달되지 않은 것입니다. 답변은 git 저장소 안의 마크다운 파일에 적혀 있고, 그걸 열어보는 사람이 없으면 영원히 거기 있습니다. 사장님 입장에서는 "시켰는데 감감무소식"으로 느껴질 수밖에 없습니다.

게다가 26일째 열려 있는 그 요청의 내용이 하필 "맥과 윈도우가 서로의 데이터를 조용히 무시하거나 유실한다"는 버그 보고입니다 — 사장님 가설과 정확히 같은 문제가 이미 한 달 전에 발견됐고, 아직 안 닫혀 있습니다.

같은 실수가 이미 한 번 더 있었습니다

CLAUDE.md에 기록된 2026-08-23 사건입니다. 예나 상담 자동 스케줄이 "로컬 PC 상태와 무관하게 돈다"고 설명돼 있었는데, 실제로는 로컬 PC 파일에만 등록돼 있어서 Claude Code가 켜져 있어야만 발화하는 방식이었습니다. 사장님이 직접 지적해서 claude.ai 서버 Routine으로 옮겼습니다.

공통 원인 — 한 문장

지금까지 겪은 문제 셋(예나 스케줄, 텔레그램 2일 지연, 26일째 안 닫힌 요청)은 전부 같은 뿌리입니다 — "사람 PC가 켜져 있어야만 돌아가는 구조." 서버를 상시 가동으로 바꾸는 것(7번의 $7)이 중요한 진짜 이유가 속도가 아니라 바로 이것입니다. 항상 깨어 있는 한 곳이 생기면, 맥이 꺼져 있든 윈도우가 꺼져 있든 큐를 대신 지켜보고 사장님께 텔레그램으로 알려줄 수 있습니다.

오늘 만든 것 — 방치 감지기

scripts/check_request_queue.py를 새로 만들어 실제로 테스트했습니다. requests/open/을 훑어 방치 일수를 계산하고, 답변이 달렸는데도 안 닫힌 건을 따로 표시합니다(위 표가 그 실제 출력입니다). 방치 건이 있으면 종료코드 1로 끝나므로, 서버가 켜지면 이걸 주기 실행해서 텔레그램 알림으로 바로 연결할 수 있습니다.

5. API 중앙 관리 — 요청하신 것과, 그대로 하면 안 되는 부분

요청: "API도 중앙식으로 전체를 박새로이가 관리해서, 더 이상 내가 관리하거나 타이핑하지 않아도 되는 시스템."

먼저 안전 문제 하나

이 저장소는 GitHub Pages로 전 세계에 공개됩니다. 여기에 실제 토큰을 넣으면 비공개 폴더에 두든, 나중에 지우든 커밋하는 순간 이미 유출입니다(git 히스토리에 남습니다). 그래서 "전부 한곳에 모아두기"를 그대로 구현하지 않고, 값과 대장을 분리했습니다.

어디에무엇이
대장 (공개 OK)apps/_shared/api_registry.json키가 있는지 · 어디 있는지 · 발급됐는지 · 언제 확인했는지
값 (비공개)Render 환경변수 · 기기 로컬 · 브라우저실제 토큰 문자열

이렇게 해도 목적은 그대로 달성됩니다. 사장님이 안 하고 싶으신 건 "무슨 키가 어떤 상태인지 기억하고 챙기는 일"인데, 그 일이 사람 머리에서 대장으로 넘어가기 때문입니다. 직접 하셔야 하는 건 최초 발급 한 번뿐이고, 그 뒤로는 대장이 기억합니다.

6. 제가 할 수 있는 것 / 사장님만 할 수 있는 것

"활성화시켜줘"라고 하셨는데, 솔직하게 경계를 그어 말씀드립니다.

❌ 이 세션에서 제가 못 하는 것

  • Render 플랜을 무료 → 유료로 바꾸기 (결제 수단이 걸린 계정 작업)
  • 서버에 접속해 상태 확인하기 (샌드박스가 해당 도메인을 403으로 차단)
  • 봇 서버 코드 수정·배포 (그 코드가 이 저장소에 없음 — 이 세션은 releasepilot-reports로만 스코프가 제한돼 있습니다)
  • 노션·OpenAI·유튜브 API 키 발급 (본인 로그인 승인 필요)

✅ 제가 지금 한 것 / 할 수 있는 것

  • 활성화 상태를 코드 근거로 판정 (이 리포트)
  • 가격을 실제로 검증 — 이전 리포트가 "가격은 미확인"으로 남긴 공백을 메움
  • 서버가 켜진 뒤 무엇부터 열리는지 순서 정리

8. 채팅으로 일이 되게 하는 순서

"채팅을 통해서 일이 될 수 있도록"에 대한 실행 경로입니다. 위에서부터 순서대로.

  2. 전환 완료를 알려주기 (사장님 · 1분) — 그 뒤 작업은 제가 이어받습니다.
  3. 브레인와이어 채팅 퀴즈부터 열기 — 4단계 질문 부품이 이미 만들어져 있고 앱을 열어야만 보이는 상태입니다. 서버가 안 자면 텔레그램에서 바로 받게 할 수 있습니다(가장 빠른 성과).
  4. 세콤 팔로업(4시간 재질문) 켜기 — 이력서 빈칸을 봇이 먼저 물어보고, 답장만 하면 데이터가 쌓입니다.
  5. 세콤 쇼츠 파이프라인 TODO 5단계 처리 (사장님) — 노션 DB화 · 노션 토큰 · TTS 키 · 유튜브 OAuth. 이건 서버 비용과 별개로 키가 없으면 아무것도 안 돕니다.
  6. 알바/외주 자동 탐색은 대상 채널 확정 후 설계 — 위 3번에서 적은 대로 아직 기획서에 없는 신규 기능입니다.
