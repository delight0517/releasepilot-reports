GitHub Pages류 정적 사이트에는 SEO 설정이 왜 "선택"이 아니라 "필수"인가

기본값의 함정

GitHub Pages, Netlify, Vercel 같은 정적 호스팅은 "URL이 생긴다"와 "구글이 그 URL을 안다"를 혼동하게 만든다. 사이트가 배포됐다고 자동으로 검색에 뜨는 게 아니다 — 실제로 이 허브의 11개 사이트가 오늘 이전까지 단 하나도 title/description 메타태그가 없었고, sitemap.xml에는 최근 만든 사이트 절반이 빠져 있었다. "일단 만들면 된다"는 가정이 틀렸다는 직접적 증거다.

1. 왜 정적 사이트가 특히 더 취약한가

  • 백링크가 0에 수렴 — 워드프레스 블로그 등 기존 CMS 사이트는 플러그인이 기본 사이트맵·메타태그를 자동 생성해주지만, 직접 짠 정적 HTML은 아무것도 자동으로 안 붙는다.
  • 공유 미리보기가 깨진다 — OG 태그가 없으면 카카오톡/트위터에 링크를 붙였을 때 제목도 이미지도 없는 텅 빈 카드로 뜬다. 이건 SEO보다 먼저, 지금 당장 신뢰도를 깎는 문제다.
  • 신생 도메인 페널티 — delight0517.github.io는 만들어진 지 얼마 안 된 하위 경로라 구글이 "이게 진짜 사이트인지" 판단할 기존 신호가 거의 없다. 메타데이터가 완비돼 있어야 그나마 있는 신호(관련성)라도 최대한 활용할 수 있다.

3. 아직 안 끝난 것 — 백링크는 시간이 필요하다

메타태그·sitemap·Search Console은 "구글이 존재를 알게 하는" 최소선이고, 순위를 끌어올리는 건 다른 사이트가 이 사이트를 링크하는 빈도(백링크)다. 이건 하루 만에 만들 수 없다 — 브런치 글, 아트스테이션 프로필, 인스타그램 바이오 링크 등 이미 있는 채널에서 꾸준히 이 허브 URL을 언급하는 것이 가장 현실적인 축적 경로다. 자세한 원리는 아래 SEO 기초 가이드에 다이어그램으로 정리해 뒀다.
